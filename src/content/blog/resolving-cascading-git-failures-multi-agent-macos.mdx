<h2>Executive Summary</h2>

<p>Over a six-week period, a macOS development workstation running multiple concurrent AI coding assistants experienced escalating git failures that progressed from repository-level issues to kernel-level file system deadlocks. The root causes traced to: (1) an AI assistant creating a phantom parent git repository at the Desktop level, (2) multiple AI agents racing on shared lock files, and (3) iCloud's sync daemon failing to materialize a 41-byte git metadata file, freezing the entire sync pipeline.</p>

<p>This case study documents the diagnostic methodology, the specific error signatures, and the resolution patterns that emerged across all five incidents.</p>

<h2>The Setup</h2>

<p>The environment in question is a macOS workstation used by a solopreneur developer running multiple concurrent AI coding assistants — Claude Code, Aider, Hermes, Droid, Mistral Vibe, and Kimi Code — alongside automated pipelines and web properties. iCloud Desktop &amp; Documents sync was enabled. Git was the shared version control layer across everything.</p>

<p>Technologies involved: Git, macOS iCloud File Provider (<code>bird</code>), endpoint security software, Node.js (GitNexus), and the AI agents listed above.</p>

<h2>Incident 1: The Phantom Desktop Repository (June 5, 2026)</h2>

<h3>Symptom</h3>

<p>Multiple projects on the Desktop began reporting <code>../../soakatlas</code> in <code>git status</code> output, despite that project being renamed months prior. <code>git status</code> in any project would hang for 10–30 seconds. Some AI tools could not "see" the correct project boundaries.</p>

<h3>Root Cause</h3>

<p>Forensic investigation traced the issue to May 1, 2026, when Kimi Code encountered a <code>.git</code> folder at the Desktop level. It attempted to "fix" this by initializing a proper git repository at <code>~/Desktop/.git</code>, writing <code>*</code> (ignore all) to <code>~/Desktop/.gitignore</code>, and manually un-ignoring only the <code>SoakAtlas</code> folder.</p>

<p>This created a "master" git repository that swallowed every project subdirectory. When git climbed the directory tree looking for <code>.git</code>, it found the Desktop parent and began scanning the entire Desktop contents.</p>

<h3>Error Signatures</h3>

<pre><code># In any project subdirectory:
git status
# Output included:
#   ../.gitignore
#   ../../soakatlas</code></pre>

<h3>Diagnostic Commands</h3>

<pre><code># Verify phantom repo exists
git -C ~/Desktop log -n 1

# Check for Desktop-level git metadata
ls -la ~/Desktop | grep .git</code></pre>

<h3>Resolution</h3>

<pre><code>rm -rf ~/Desktop/.git
rm ~/Desktop/.gitignore</code></pre>

<p><strong>Lesson:</strong> AI assistants operating on file system structures need explicit boundaries. The "simplest fix" from one agent's context window can create system-wide architectural problems.</p>

<h2>Incident 2: Endpoint Security Killing Git Processes (June 5, 2026)</h2>

<h3>Symptom</h3>

<p><code>git push</code> commands would authenticate to GitHub successfully, then immediately terminate with <code>zsh: killed</code> before any data transfer.</p>

<h3>Root Cause</h3>

<p>System-level endpoint security software (identified by Team ID <code>Q6L2SF6YDW</code>) was treating the git binary's network activity as suspicious. The security tool was actively sandboxing and killing the process mid-flight.</p>

<h3>Error Signatures</h3>

<pre><code>git push origin main --no-verify
# zsh: killed     git push origin main --no-verify</code></pre>

<h3>Diagnostic Commands</h3>

<pre><code># Identify security restrictions
sudo pkill -9 git
# Output: "pkill: signalling pid NNN: Operation not permitted"
# Indicates SIP or endpoint security protection</code></pre>

<h3>Resolution</h3>

<pre><code># Use direct HTTPS URL bypassing origin tracking
git push https://github.com/user/repo.git main

# Disable optional locks to reduce security scan triggers
GIT_OPTIONAL_LOCKS=0 git push --no-verify</code></pre>

<p>Long-term: coordinate with security team to whitelist git processes.</p>

<p><strong>Lesson:</strong> High-frequency automated git activity triggers endpoint security heuristics. AI agents committing in loops look like malware to security software.</p>

<h2>Incident 3: Multi-Agent Lock File Race Condition (June 19, 2026)</h2>

<h3>Symptom</h3>

<p>Every project on the workstation reported stale <code>index.lock</code> files. No git commands could complete. Four separate AI coding agents were active simultaneously.</p>

<h3>Root Cause</h3>

<p>Four AI agents (Hermes, Droid, Mistral Vibe, Aider) were each running git operations across overlapping projects. In the background, GitNexus (a code relationship indexer running via Node.js) was also executing git commands for symbol mapping.</p>

<p>This created a classic race condition: Agent A would create <code>index.lock</code>, Agent B would try to create its own before Agent A finished, GitNexus would attempt a background status check, and all three would collide.</p>

<h3>Diagnostic Commands</h3>

<pre><code># Find all stale lock files
find ~/Desktop ~/CascadeProjects ~/desertsoak -name "index.lock" -path "*/.git/*"

# Identify hidden GitNexus processes
ps auxww | grep -i "gitnexus" | grep -v grep</code></pre>

<h3>Resolution</h3>

<pre><code># Kill all git and gitnexus processes
pkill -9 -f gitnexus
pkill -9 -f git

# Deep clean all lock files
find ~/Desktop ~/CascadeProjects ~/desertsoak -name "index.lock" -path "*/.git/*" -delete 2>/dev/null</code></pre>

<p><strong>Lesson:</strong> Multi-agent workflows require process coordination. Without it, agents compete rather than collaborate, and the shared resource (git lock files) becomes a bottleneck.</p>

<h2>Incident 4: iCloud File Provider Deadlock (July 6, 2026)</h2>

<h3>Symptom</h3>

<p>Repository completely frozen. <code>git status</code> would hang indefinitely. Even <code>cp</code> commands to copy the <code>.git</code> directory would block with 0% CPU usage.</p>

<h3>Root Cause</h3>

<p>The <code>cp</code> process was stuck at the kernel level attempting to read a single file: <code>.git/AUTO_MERGE</code>. This 41-byte file was stale orphaned merge scratch state, dated over a month old.</p>

<p>macOS's iCloud File Provider daemon (<code>bird</code>) could not materialize this file. Because the file resided in an iCloud-managed folder (Desktop), the sync daemon held a kernel-level lock while trying to resolve the file's cloud state. This blocked all file system operations on the repository.</p>

<h3>Cascading Failures</h3>

<p>After resolving the <code>AUTO_MERGE</code> deadlock, three secondary issues emerged:</p>

<ul>
<li><strong>Nested worktree repositories:</strong> Claude Code had created <code>.claude/worktrees/</code> folders containing their own <code>.git</code> metadata, triggering more iCloud confusion</li>
<li><strong>Ghost lock file:</strong> A previously killed git process left <code>.git/packed-refs.lock</code> behind</li>
<li><strong>Embedded repository warnings:</strong> <code>git add .</code> warned about adding embedded repositories</li>
</ul>

<h3>Resolution Sequence</h3>

<pre><code># Step 1: Kill stuck processes
killall -9 cp git

# Step 2: Remove the stale merge file
rm -f ~/Desktop/project/.git/AUTO_MERGE

# Step 3: Restart iCloud sync daemon
killall -9 bird

# Step 4: Remove nested scratchpad repos
rm -rf .claude/

# Step 5: Clear ghost lock
rm -f .git/packed-refs.lock</code></pre>

<p><strong>Lesson:</strong> iCloud Desktop &amp; Documents sync is fundamentally incompatible with Git repositories. The <code>bird</code> daemon cannot handle git's high-frequency, small-file metadata operations. Repositories in iCloud-managed folders will eventually deadlock.</p>

<p><strong>Long-term fix:</strong> Move all code repositories to non-iCloud locations (e.g., <code>~/Projects/</code> or <code>~/Code/</code>).</p>

<h2>Incident 5: HTTP/2 Buffer Overflow on Large Rebuild (July 13, 2026)</h2>

<h3>Symptom</h3>

<p><code>git push</code> would authenticate to GitHub, then hang immediately after. The repository was 6 commits ahead after a massive SolidJS migration and rebranding.</p>

<h3>Root Cause</h3>

<p>The push hang was isolated to HTTP/2 buffer overflow. The 6 commits contained large JSON data exports and rebuilt assets that exceeded the default git post buffer.</p>

<h3>Diagnostic Commands</h3>

<pre><code># Verbose push to identify hang point
GIT_CURL_VERBOSE=1 git push origin main

# Output showed:
# &lt;= Recv header: HTTP/2 200
# == Info: Connection #0 to host github.com left intact
# Then indefinite hang — indicating successful auth but stalled upload</code></pre>

<h3>Resolution</h3>

<pre><code># Increase post buffer to 500MB
git config http.postBuffer 524288000

# Force HTTP/1.1 to avoid HTTP/2 multiplexing issues
git config http.version HTTP/1.1</code></pre>

<h3>Alternative: Incremental Push</h3>

<p>For extremely large commits, push incrementally:</p>

<pre><code># Push one commit at a time to isolate heavy payloads
git push origin main~5:main
git push origin main~4:main
# ... continue until all commits are pushed
git push origin main</code></pre>

<p><strong>Lesson:</strong> HTTP/2's multiplexing can fail on large git payloads. HTTP/1.1 provides more predictable upload behavior. Incremental pushing is a reliable fallback when single large commits exceed transport buffers.</p>

<h2>Diagnostic Framework: What Worked</h2>

<p>Across all five incidents, a consistent diagnostic pattern proved effective:</p>

<h3>1. Pattern Recognition Across Time</h3>

<p>Searching past sessions and connecting current symptoms to previous incidents was critical. When <code>../../soakatlas</code> appeared in June, the trail led back to the May 1st session where the phantom repository was created.</p>

<h3>2. Terminal Output Analysis</h3>

<p>Reading visible terminal snapshots identified process state (running, zombie, killed), error signatures (<code>zsh: killed</code>, <code>Operation not permitted</code>), lock file locations, and path confusion.</p>

<h3>3. Command Sequencing</h3>

<p>Explicit, reviewable copy-paste command sequences prevented automated actions from compounding problems. Each step was visible and verifiable before the next began.</p>

<h3>4. External Research</h3>

<p>Developer forums, Apple support threads, and Stack Overflow provided explanations for <em>why</em> iCloud + git metadata fails, why endpoint security kills git, and why HTTP/2 hangs on large payloads — not just <em>what</em> to do about it.</p>

<h2>Preventive Measures</h2>

<p>Based on these incidents, the following practices are now standard:</p>

<ol>
<li><strong>Repository Location:</strong> All git repositories live in <code>~/Projects/</code>, outside iCloud-managed folders</li>
<li><strong>Agent Coordination:</strong> Before git operations, verify which AI agents are active: <code>ps aux | grep -E "(claude|aider|hermes|droid)"</code></li>
<li><strong>Lock File Monitoring:</strong> Weekly scan for stale lock files: <code>find ~/Projects -name "index.lock" -path "*/.git/*"</code></li>
<li><strong>Security Whitelisting:</strong> Git binary and common IDE processes are whitelisted in endpoint security</li>
<li><strong>Buffer Pre-configuration:</strong> <code>http.postBuffer</code> set to 524288000 globally for repositories handling large assets</li>
</ol>

<h2>Conclusion</h2>

<p>The six-week cascade revealed a systemic pattern: AI coding assistants optimize for immediate task completion without system-level awareness. When multiple agents share a development environment, their individually "helpful" actions compound into race conditions, phantom repositories, and security conflicts.</p>

<p>The most effective diagnostic approach proved to be one with read-only observation — capable of connecting symptoms across time, reading terminal output in context, and providing explicit human-reviewed commands. In an ecosystem where AI agents can write code but not necessarily understand consequences, a "watch-only" debugging partner provided the oversight layer that prevented further escalation.</p>

<p>For development teams using multiple AI coding tools, these incidents highlight the need for agent coordination protocols, repository isolation from cloud sync services, and explicit security whitelisting for automated git workflows.</p>
